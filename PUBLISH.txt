HOW TO PUBLISH A NEW VERSION (keeps the same HTTPS link)
--------------------------------------------------------
First time: follow the Netlify steps below and note your link
(for example https://your-name.netlify.app).

Every later update:
 1. Open https://app.netlify.com, choose your site, then the Deploys tab.
 2. Drag the NEW folder (with the new index.html and sw.js) onto the
    "Drag and drop your site output folder here" box.
 3. Wait for "Published". The link stays exactly the same.
 4. On any device, open the app and press Updates (or wait: it checks on its
    own). The "Update now" bar appears, press it, and the new version loads.
    Saved records stay on that device.
Important: every new release must have a new version number in sw.js
(APP_VERSION and CACHE_NAME), because that is how devices notice an update.
Always upload to the SAME site. A different address starts with empty records.

OWNER RECORDS ACROSS DEVICES

This release is connected to the hosted Supabase project. Owner cloud sign-in
and sync require an internet connection. Employee accounts, permissions,
notifications, and device preferences remain local.

1. Publish the contents of this ZIP to the same HTTPS website address used for
   the existing app. The business-record table and owner access policies are
   already installed.
2. Keep a backup of local-only records. If the records currently exist only
   on another device or a different website address, use that device's Owner >
   Your data > Backup, then restore the file on this website before creating
   the cloud account.
3. On the first device, select Admin / Owner, choose Create account, then
   register the owner's username and a unique password/code of at least 12
   characters. The account is created in the cloud and existing local records
   upload if no cloud record exists yet.
4. On every other device, open the exact same HTTPS app address and sign in
   as Admin / Owner with that username and password/code.

The owner password is a reusable access code: anyone with the username and
code can access the owner's records. Keep it private. When cloud records
already exist, signing in loads them instead of replacing them; a local
safety snapshot is kept before local records are replaced. Keep backups. The
app checks for changes about every 20 seconds and
uses optimistic conflict checks; if two devices edit at once, it stops syncing
instead of silently replacing either copy. Resolve the conflict by backing up
both devices and using one device at a time before signing in again.

EMPLOYEE ACCESS CODES AND OWNER PERMISSION (V1.350)

The owner dashboard has an Employee access codes section. Press Generate access
code and give the code to the employee. A new employee must enter that code when
creating an Employee / Agent account. Codes stay active: they never expire and
can be reused. Only the owner can end a code, by pressing Revoke. After registering, the employee
account is Waiting for approval and cannot sign in until the owner presses
Approve in the Employee accounts table. The owner can also Block or Unblock an
employee later; a blocked employee who is signed in is returned to the login
screen. Employee accounts created before V1.350 stay approved.

ACCOUNT ROLES

Choose Admin / Owner or Employee / Agent at the top of the sign-in screen.
Create an account for that role, then sign in with its username and password.
Usernames can include spaces, dots, underscores, and hyphens. The same
username may be registered separately for both roles. Creating an account
signs the user into its matching dashboard. The owner has a read-only
dashboard for sales activity, daily sales, expenditure, product types,
Shop and Store piece counts, low-stock and out-of-stock counts, plus read-only
stock quantities by product and location. The owner can also see employee
account status and last sign-in, plus recent employee-recorded product, stock,
sales, and expense activity. "Active" means the account has a recent session
in this browser; other devices cannot be monitored. The employee can add
products with separate Shop and Store starting quantities, receive stock into
either location, adjust each location independently, and record sales against
the selected Shop or Store balance. Sales are deducted from that location
only; cancelling a sale restores stock to its original location unless its
product has been deleted. The employee can also enter expenses. Existing
single stock counts are carried into Store when the app is updated. A maximum
of three employee accounts can be registered in the current browser;
additional employee registrations are blocked, while existing employees can
still sign in.

Work entered before employee activity tracking was added may not show an
employee name. New product, stock, sale, and expense entries are attributed
to the signed-in employee.

Local employee accounts and offline records are stored in browser storage;
role-specific screens alone are not secure permissions. For owner cloud
records, Supabase Auth protects sign-in and row-level security limits database
access to the signed-in owner. Keep the public publishable key in the app only
with row-level security enabled; never put a service-role key in browser code.
The owner password/code grants access to the business data; keep it private.

The dashboard Updates button reloads the latest records saved in that
browser. Use the three-dot settings menu to choose from 11 color themes;
theme preferences are saved on that device.
